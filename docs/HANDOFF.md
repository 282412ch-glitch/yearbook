保留以下约束：

1. 不改写已应用的迁移 SQL，包括换行。四份 SQL 当前为 LF，数据库按 SHA256 检查；新功能追加新迁移。
2. `scopeRecordIds` 是本次授权范围，`sourceRecordIds` 是实际引用，不能混同。第一次章节只能用用户已标记的记录；来源 ID 有效不代表模型文字在语义上一定真实。
3. `ModelRequest.expectedProfileUpdatedAt` 只用于本地保护，不能发给模型。运行中修改配置后，后续请求应拒绝继续，不能悄悄改发。
4. 模型等待不占用写队列；取消/重试捕获原执行代次，不能让迟到结果写库或取消下一次尝试。关闭先在 `preClose` 停模型、AI、导出，再于 `onClose` 关闭数据库。
5. 恢复开始前的慢请求在 body 解析后也必须检查维护代次。备份/恢复副本清空凭据引用与能力，原库不被创建备份修改，外来备份不能绑定本机旧 Key。
6. UI 采用记录草稿只预填编辑器，用户保存后才改原记录；整册采用前必须保留当前手动版本。
7. 测试不可使用正式 `data`。浏览器沿用 Tabbit，截图按回执 `result.nextAction.path` 读取；超时只重试纯截图，不能重放业务操作。

本轮已于 2026-09-12 重新核对官方 Responses 迁移与 function calling 文档。按用户授权尝试多模型协作，其他模型因供应错误或不支持未完成任务；实际成果由主线与 GPT-6 Astra 子代理共同完成。没有待合并的代理成果。

